# ADR-0003 — Pre-launch runtime safety gate

**Дата:** 2026-07-29
**Автор:** Lead Software Architect
**Статус:** Accepted for synthetic development only

## Контекст

`ADR-0001` и `ADR-0002` устанавливают, что весь текущий каркас (`apps/api`,
`apps/web`, Campaign Read Model, Campaign Event Log) работает исключительно
на синтетических данных и что `PRODUCTION_LAUNCH_GATE` заблокирован. До сих
пор это ограничение существовало только как текст в документации (ADR,
README) — ни один программный механизм не проверял его при старте процесса.
Один неверно выставленный переменной окружения флаг (например, случайный
`NODE_ENV=production` в CI или в чужом окружении) не встретил бы никакого
технического сопротивления.

Это решение вводит программный, проверяемый при каждом старте механизм,
который делает утверждения ADR-0001/ADR-0002 технически принудительными, а
не только документальными.

## Решение

Для **синтетической DEVELOPMENT-разработки** вводится централизованный
runtime policy `apps/api/src/runtimePolicy.ts`, проверяемый в
`apps/api/src/server.ts` синхронно, до создания PostgreSQL-пула и до
`app.listen()`.

1. **До отдельного `PRODUCTION_LAUNCH_GATE` поддерживается только synthetic
   runtime.** Единственное допустимое состояние процесса:

   ```
   LEASEMIND_RUNTIME_MODE=synthetic
   LEASEMIND_PRODUCTION_LAUNCH_GATE=blocked
   LEASEMIND_ALLOW_REAL_PII=false
   LEASEMIND_ALLOW_REAL_PAYMENTS=false
   LEASEMIND_ALLOW_PROTECTED_REVEAL=false
   LEASEMIND_ALLOW_PRODUCTION_ADAPTERS=false
   ```

2. **Реальные ПДн запрещены.** `LEASEMIND_ALLOW_REAL_PII` должен оставаться
   `false`; любое иное значение останавливает запуск процесса.
3. **Реальные платежи запрещены.** `LEASEMIND_ALLOW_REAL_PAYMENTS` должен
   оставаться `false`; любое иное значение останавливает запуск процесса.
4. **Раскрытие защищённых данных запрещено.** `LEASEMIND_ALLOW_PROTECTED_REVEAL`
   должен оставаться `false`; любое иное значение останавливает запуск
   процесса.
5. **Production adapters запрещены.** `LEASEMIND_ALLOW_PRODUCTION_ADAPTERS`
   должен оставаться `false`; любое иное значение останавливает запуск
   процесса.
6. **Безопасные значения по умолчанию.** Отсутствие любой из шести
   переменных трактуется как самое строгое безопасное значение
   (`synthetic` / `blocked` / `false`) — отсутствие переменной никогда не
   ослабляет проверку.
7. **Строгий разбор булевых значений.** Для `LEASEMIND_ALLOW_*` допустимы
   только точные строки `"true"`/`"false"`. Любое другое значение
   (`"TRUE"`, `"1"`, `"yes"`, пустая строка, произвольный текст) —
   немедленная ошибка запуска, а не молчаливая трактовка как `false`.
8. **`NODE_ENV` не участвует в этой проверке.** Runtime policy не читает и
   не проверяет `NODE_ENV` ни в каком виде — обхода через стандартный
   Node.js-флаг окружения не существует.
9. **Порядок проверки.** `enforceRuntimeSafetyGate()` вызывается первой
   инструкцией `main()` в `server.ts`, до `loadConfig()`, до создания
   PostgreSQL-пула (`createPool`) и до `app.listen()`. Нарушение полностью
   останавливает процесс (`process.exit(1)`) прежде, чем предпринимается
   попытка подключения к базе данных или открытия порта.
10. **Безопасная диагностика.** Сообщение об ошибке называет только имя
    нарушенной переменной и её требуемое значение. Оно никогда не включает
    фактическое считанное значение, `DATABASE_URL`, пароли, токены или
    произвольные переменные окружения.

## Явно НЕ входит в это решение

- **Deployment этим решением не разрешается.** Наличие корректного
  synthetic/blocked runtime policy не является approval production
  окружения, инфраструктуры, хостинга или каких-либо deployment-действий.
- **Изменение одного env-флага не может открыть production.** Namespaced
  `LEASEMIND_*` переменные не имеют "production mode", "launch override",
  bypass-флага или emergency-disable — единственный путь изменить это
  поведение в будущем требует нового кода, новой проверки и нового
  ADR/утверждения DEVELOPMENT, а не изменения значения переменной
  окружения существующего кода.
- **Будущий production launch требует отдельного кода, проверки и
  утверждения.** Этот ADR не проектирует и не описывает, как будет выглядеть
  production runtime — он фиксирует только то, что до отдельного,
  сознательно спроектированного и утверждённого решения текущий код
  технически не может перейти в производственный режим через переменные
  окружения.
- Это не изменение продукта, UX, бизнес-логики, платёжной модели или
  юридических правил — гейт затрагивает только технический bootstrap
  процесса `apps/api`.
- Это не изменение Campaign Read Model, Campaign Event Log или Matching
  Engine controlled artifacts — их код, миграции и данные не затронуты.

## Последствия

- Любой запуск `apps/api` с `LEASEMIND_RUNTIME_MODE` отличным от `synthetic`,
  `LEASEMIND_PRODUCTION_LAUNCH_GATE` отличным от `blocked`, любым
  `LEASEMIND_ALLOW_*=true` или синтаксически некорректным булевым значением
  завершается ошибкой до подключения к PostgreSQL и до открытия порта.
- Существующие synthetic local/CI команды (`npm run dev`, `npm run test`,
  CI workflow `Application Foundation`) продолжают работать без изменений,
  поскольку безопасные значения по умолчанию совпадают с их текущим
  окружением.
- Health API (`GET /api/v1/health/live`, `GET /api/v1/health/ready`) не
  раскрывает значения security-флагов — их состав ответа не менялся.
- Реальный production launch в будущем потребует отдельного, сознательно
  написанного и утверждённого кода (не переменной окружения) и отдельного
  решения DEVELOPMENT/Founder — этот ADR его не разблокирует автоматически.
